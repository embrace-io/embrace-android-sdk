2026-08-17 · 02:50–04:39 · Pixel 7 Pro, five single-pass probes then 10 tapped legs × 20 iterations on 9.2.0-SNAPSHOT · X29 — first attribute-joined campaign, plus the flush-race investigation that made it possible

The wall: with the tap verified free (X27), one probe pass showed its output never lands under macrobenchmark — the harness force-stops the process 1–3 s after launch, and the 10 s deferred flush dies with the queue on every single launch. Shortening the delay did not save it: 1/50 at 3 s, 1/50 at 1 s. The fix is event-driven, not a faster timer: flush when the startup trace's ROOT span (emb-app-startup-cold/-warm) ends, plus a 150 ms grace — the grace because child spans are recorded retrospectively after the root ends, so end-call order is not timestamp order and keying on any child's name would couple to emitter-internal ordering. Measurement safety is architectural: when the root ends, every trace event that determines window and TTID already exists, so the flush's CPU cannot perturb post-hoc derivation. Result: 50/50 launches emit where the timer managed 1/50.
