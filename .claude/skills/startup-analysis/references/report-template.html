Reading the breakdown

The span decomposes into three big costs plus a tail: persisted-config-load (27.5%) — cached-config read, the most variable section in this run (1.9–20.4 ms); otel-tracer-init (25.5%) — assembling the OTel SDK instance (tracer provider, resource, processors); and payload-source-init (12.6%). Everything else is ≤ 7% each. All 20 iterations in this pass came in clean (0/20 flagged CONTENDED in the scheduling table), so the 44–74 ms spread across runs reflects section-level variance rather than scheduling noise.
