Regressions are judged on fast-pass numbers, per the runbook.

Reading the breakdown

The window decomposes into two big costs plus a tail: span-service-init (39.6%), almost all of which is otel-tracer-init (33.0%) — assembling the OTel SDK instance (tracer provider, resource, processors); and persisted-config-load (25.1%) — the cached-config read, as always the most variable section (2.4–15.3 ms). Everything else is ≤ 7.2% each. Off the critical window, the largest concurrent sections are install-native-crash-signal-handlers (13.1 ms median), load-embrace-native-lib (9.3 ms), and record-startup (5.6 ms) — full list in the summary files. TTID median 867 ms is in line with the 2026-08-11 reference (~865 ms); pass 1's TTID (925 ms) drifted with the same slow-pass effect.
